## Request/Response Flow - Complete Booking Journey

┌─────────────────────────────────────────────────────────────────────────┐
│                         USER BOOKING JOURNEY                            │
└─────────────────────────────────────────────────────────────────────────┘

1. User visits homepage
   └─► GET /api/events
       └─► Returns active future events with prices ✨
           └─► Frontend displays sorted cards with price badges ✨

2. User clicks "View Details"
   └─► Modal shows event details including price ✨
       └─► If past event: shows warning + disabled button ✨

3. User clicks "Book Event"
   └─► Checks if logged in
       └─► If not: redirects to login
       └─► If yes: proceeds to booking

4. User submits booking
   └─► POST /api/bookings
       └─► Backend validates:
           ├─► Event exists?
           ├─► Event is_active? ✨
           ├─► Event date >= today? ✨
           └─► User is Participant?
       └─► If valid: creates booking
       └─► If invalid: returns 422 error ✨

5. User sees confirmation
   └─► Booking stored in database
       └─► User can view in "My Bookings"

## Key Improvements Summary

┌─────────────────────────────────────────────────────────────────────────┐
│                         BEFORE vs AFTER                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  FEATURE 1: EVENT PRICING                                              │
│  ┌──────────────────────────┬──────────────────────────────────────┐   │

│  │ No price information     │ Price displayed on cards & modals    │   │

│  ┌──────────────────────────┬──────────────────────────────────────┐   │
│  │ BEFORE                   │ AFTER ✨                             │   │
│  ├──────────────────────────┼──────────────────────────────────────┤   │
│  │ Random order             │ Always sorted by date ASC            │   │
